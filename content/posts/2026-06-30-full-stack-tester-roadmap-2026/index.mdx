Back in 2022 I drew [my own automation tester roadmap](/tester-roadmap-2022) because roadmap.sh still hadn't shipped theirs. Four years later the landscape has shifted enough that an update isn't enough — the role itself has changed.

The term **Full Stack Tester** is becoming real. Companies want someone who can write a Playwright test, wire it into a GitHub Actions pipeline, spin up a container to run it, read the Grafana dashboard when something breaks, and — increasingly in 2026 — use AI tools to do all of the above faster.

This is not "learn everything". It's a map of what the intersection of DevOps + QA + Quality Engineering looks like right now, with AI layered on top.

---

## The five pillars

**Foundation** — the stuff that underpins everything else. HTML, a programming language (TypeScript or Python, pick one and go deep), Git, HTTP, and Linux basics. Non-negotiable.

**Testing Craft** — the human side. Test strategy, exploratory testing, BDD, shift-left. Automation without craft is just expensive flakiness.

**Automation Engineering** — Playwright has won E2E for now. But you also need API testing, unit testing, performance testing (k6), and a basic understanding of mobile. Visual and accessibility testing are no longer optional if you work on user-facing products.

**DevOps** — CI/CD pipelines, Docker, Kubernetes at least to the level of "I can read what broke". Cloud is table stakes. Monitoring and observability are where bugs actually hide.

**AI Skills** — this is the new section. In 2026, not using AI tools means you're slower than someone who does. More importantly, someone has to *test AI systems*, and that's a skill set that barely existed two years ago.

---

## On AI skills specifically

There are two distinct things here that people conflate:

1. **Using AI to do your job faster** — Copilot for writing boilerplate tests, Claude Code for debugging pipelines, prompt engineering to generate test cases from specs. This is table stakes by 2026.

2. **Testing AI systems** — hallucination detection, bias testing, prompt injection, behavioral consistency. If your company ships an LLM-powered feature, someone needs to know how to break it. That someone is increasingly the tester.

The [WebTestBench benchmark](/webtestbench-ai-testing) shows AI agents still top out at ~26% F1 on autonomous web testing. The gap between "AI-assisted" and "AI-autonomous" is still very much a human opportunity.

## What changed since 2022

The 2022 map was "an automation tester who knows some DevOps". The 2026 map is something closer to a quality engineer who can operate across the full delivery pipeline.

The biggest additions:

- **Playwright** replaced Selenium as the default E2E tool
- **k6** is the go-to for performance (Gatling still valid for JVM shops)
- **OpenTelemetry** is the observability standard now
- **AI skills** — both for tooling and for testing AI-powered systems
- **Contract testing** went from "interesting idea" to "required in microservices"
- **Accessibility** moved from optional to "your lawyers will ask about this"

What I dropped from 2022: React/Angular (not a tester's job unless you're in a tiny team), SysAdmin (K8s replaced most of that), WinAppDriver (niche).

The core hasn't changed: write good tests, automate the boring parts, break things before users do. The tools just got better — and more numerous.
